## Description

A bare number does not help a student decide, but short reasons do. The AI only writes the words from the rule-based breakdown; if it fails, the app shows rule-generated reasons (`aiGenerated: false`, `fallbackUsed: true`). The AI never changes the score.

## Work needed

- Worker function `explainMatch` that loads the approved score breakdown for an authorised match and writes plain-language reasons.
- Rule-based fallback text built from the reason codes.
- Store `aiReasons`, `aiGenerated`, `fallbackUsed` on the `matches` document.
- Show the label 'AI-generated' next to AI reasons (E8.4) and let users rate reasons for the evaluation (E8.5).
- Prompt template that receives only the factor names, similarity levels and class-day overlap (no raw answers, names or contact data).
- Limit the answer to two or three short sentences in the student's language (English or Malay).

## Constraints

- Reasons name real factors and include the overlapping class days.
- No contact or private profile data goes into the prompt.

## Acceptance (how QA checks it)

Aly runs these checks and records the result in ClickUp.

- [ ] Each reason comes from the score breakdown and names real factors.
- [ ] If the AI call fails the app shows rule-generated reasons.
- [ ] Every AI reason is labelled AI-generated.
- [ ] Reasons are rated by users for the evaluation (E8.5).
- [ ] A reason for a `different` factor says so plainly, not only the good points.
- [ ] With the AI disabled, every match still shows reasons from the codes.
