## Description

Five people build screens in parallel. Without one set of tokens and components, each screen would look different and fail the
brief's usability marks. The rules (only design tokens, 48 dp touch targets, status with a word and an icon, estimates
labelled as estimates) are in [DESIGN.md](../../docs/design/DESIGN.md); this story turns them into code that the others reuse.

## Work needed

1. ✅ **Figma tokens, components and all screens.** The design source for the app.
2. ✅ **Design system resources in code.** Colours, type, shape and spacing as Android resources, with the Figma logo as the
   app logo and launcher icon.
3. ✅ **Reusable components** in `ui/common/`: `AvatarView`, `BadgeView`, `CommuteOptionView`, `EmptyStateView`,
   `InfoBannerView`, `JiranSnackbar`, `JiranTabBar`, `ListRowView`, `RoomCardView`, `SearchBarView`, `SectionHeaderView`,
   `StepProgressView`, plus the top bar layout.
4. ✅ **App shell.** `ShellActivity` hosts `nav_main.xml` and the floating tab bar (single-activity, one package per
   feature under `ui/`).
5. ✅ **Component gallery** (debug builds only, launcher "Jiran UI") so every component can be seen with its states.
6. ✅ **Announce the component list and how to use it** (Ary says done).
7. ✅ **Empty and error states as components** (Ary says done). The repository has `EmptyStateView`, `InfoBannerView`
   and `JiranSnackbar`; there is no class called an error state, so QA should check that these cover the error case.

## Acceptance (how QA checks it)

- [ ] The gallery opens from the "Jiran UI" launcher icon in a debug build and shows every component listed above.
- [ ] Every tappable component is at least 48 dp high and wide.
- [ ] Text on every background meets the 4.5:1 contrast the PRD asks for.
- [ ] A status (for example a Listing or Connection state) is shown with a word and an icon, never colour alone.
- [ ] No screen uses a colour or size that is not a token in `res/values`.
- [ ] `./gradlew lintDebug checkstyleMain assembleDebug` passes.

## Not in scope, and why

- **Screens of the other modules.** Each owner builds their own screens from these components; Ary reviews them in the PR.
- **Anything not listed above.** A new component is added by the story that first needs it, reviewed by Ary in that PR.

- 27 Oct 2026, Ary: the gallery and the "Jiran dev" launcher exist only in debug builds. This is why a debug install shows three

Computed from the hex values, not measured on a device screen.
