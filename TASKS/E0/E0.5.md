## Description

Most of NFR2 (privacy) is enforced by Firestore Security Rules, and every screen needs agreed field names. Gathan's `docs/engineering/schema.md` (merged with PR #8 on 10 Nov 2026) lists the collections with fields, writers and the stage that may read them, a stage visibility matrix, a data retention schedule and the server tasks the Worker must do.

Rules cannot run queries, only `get()` on paths built from the request or the document. That is why the draft uses deterministic IDs: `matches/{uidA_uidB}`, `listingRequests/{listingId}_{requesterUid}` and the proposed `connections/{pairId}`.

## Constraints

- All money is integer sen, field names end in `Sen` (matches `docs/engineering/api-contracts.md`).
- Photos are URLs from a free host; Firebase Storage is not used on the free plan.
- `backend/firestore.rules` denies every path it does not name (fallback rule at the end).
- UM student email only (`siswa.um.edu.my`, verified) is the baseline of every rule.
- Money is stored in sen (integer), fields end in `Sen`.
- `connections/{pairId}`, pairId = the two UIDs sorted and joined by `_`, because Rules cannot query. Only the Worker creates it (ADR-0007); the Rules deny the app create and delete.
- Gender: public `users/{uid}.gender`, `"male"` or `"female"`, required when the profile is created (E1.3).
- No class timetable or campus-day collection in the target product (Ary, 11 Nov 2026). Coordinate E1.3 to stop requiring/writing `campusDaysPerWeek`; preserve old profiles without requiring a destructive deletion. The `private/timetable` Rules are legacy. See PRD FR1.3/Module 4 and the per-trip file handoff.

## Not in scope, and why

- Cloud Functions or paid services: the server is a free Cloudflare Worker.
- Photo storage in Firebase Storage: not used on the free plan; photos are URLs from a free host (draft).
