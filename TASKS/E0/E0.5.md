## Description

Most of NFR2 (privacy) is enforced by Firestore Security Rules, and every screen needs agreed field names. Gathan's draft in `docs/schema.md` (PR #8) lists the collections with fields, writers and the stage that may read them, a stage visibility matrix, a data retention schedule and the server tasks the Worker must do.

Rules cannot run queries, only `get()` on paths built from the request or the document. That is why the draft uses deterministic IDs: `matches/{uidA_uidB}`, `listingRequests/{listingId}_{requesterUid}` and the proposed `connections/{pairId}`.

## Constraints

- All money is integer sen, field names end in `Sen` (matches `docs/engineering/api-contracts.md`).
- Photos are URLs from a free host; Firebase Storage is not used on the free plan.
- `backend/firestore.rules` today only holds the prototype rule for `_connectionChecks/{uid}` and denies everything else.
