## Description

Searching vacant rooms is the first thing a student does. The result is one Room card per vacant room (`RoomCardView`, E0.3), with monthly rent kept separate from per-trip travel estimates. A card shows five items (Ary, 11 Nov 2026): monthly price, Building name, area, one-way time and distance to the student's faculty, and the time since it was listed, with the room type as a badge on the photo; no street address and no fare (those are on details); CO₂ appears only on the detail page.

## Work needed

- Query `rooms` with `status == 'vacant'` joined to their active `listings` (building, area, photos); use the newest-first default; any price sort uses Room rent.
- Rooms screen with a search bar, the filter entry point and Room cards; an empty state when nothing matches.
- Saved rooms: a student can save and unsave a room and see the list.
- Use the sample listings from E2.4 until real ones exist.

## Constraints

- Ary, 11 Nov 2026: monthly Room rent stays separate from per-trip time/fare; true monthly cost is removed. No timetable or campus-day input. See [PRD Module 4](../../docs/product/PRD.md#module-4-apartment-to-faculty-commute-guide) and [file handoff](../../docs/plans/2026-11-11-commute-per-trip.md).

- Only active, unexpired listings appear.
- The exact Unit (block, floor, door number) is never in the public document; the Building's street address (`buildingAddress`) is public and shown on the card (Ary, 11 Nov 2026).
- Cards show an estimate label wherever cost or time is estimated.
- Before any search the Rooms tab shows the newest active listings first, with the filter chips on top. If the student saved a faculty, cards show travel time (E3.4). No location permission is needed.
