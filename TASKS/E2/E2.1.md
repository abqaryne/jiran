## Description

This is the first half of Flow A (a Host who already rents a Unit opens a vacant Room). A Host is a verified UM student who holds or is about to hold the tenancy; landlords have no account. The Host picks the building from a place search so the address and coordinates fill in by themselves and the commute calculation has a destination.

Data: the public `listings/{listingId}` (areaId, buildingName, placeId, lat, lng, totalRentSen, depositSen, genderPref, amenities, photoUrls, isSample, status, createdAt, expiresAt) and the private `listings/{id}/private/location` (exactAddress, residentUids).

## Work needed

- Create a Host-only `draft` (Gathan approved, 9 Nov 2026). E2.2 supplies the priced vacant Room gate before publication; `expiresAt` starts 30 days after publication, not draft creation.
- Create `private/location` with the exact address; public search must never read it.
- Building picker: place search that returns the building name, `placeId`, address and coordinates; a name that is not found can be typed with the area chosen by hand from `areas`.
- Post screens step 1 (Ary's components): photos, building, total rent, deposit; gender preference and amenities are chosen here too (FR2.1).
- Photo upload to the agreed free host and store the returned URLs in `photoUrls`.
- Rules: only the Host (`ownerUid`) can write the listing; only verified UM students can read it.

## Constraints

- A listing cannot be published without building name, total rent, deposit, area, one photo and one priced vacant room (the last two are finished in E2.2).
- Money in integer sen: `totalRentSen`, `depositSen`.
- Listings in the same building share the building name, which links them to reviews and the area page (E9.4).
- The Host is a UM student: sign-up already guarantees this (E1.1).
