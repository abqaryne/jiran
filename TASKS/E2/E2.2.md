## Description

Each vacant Room has its own price, and the sum over all rooms in the Unit (vacant and occupied) must never exceed the Unit's total rent, so nobody profits from subletting. The app suggests a default split by room-type weights and shows how much rent is still unallocated.

`splitRoomPrices` in `docs/engineering/api-contracts.md` already fixes the shape: a request with `totalRentSen` and a list of rooms (`id`, `type`), a response with `priceSen` per room. Weights live in `config/app.roomPriceWeights`, so they change without a release.

## Work needed

- Plain Java rule class: suggest prices from weights (master 1.3, medium 1.0, small 0.7), round to the nearest RM1 (100 sen), give the remainder to the master room.
- Validate a total: `sum(priceSen) <= listing.totalRentSen`; return the amount left (`totalRentSen - sum`).
- Create `rooms/{roomId}` documents (type, priceSen, status `vacant`/`occupied`, occupiedByUid) linked by `listingId`.
- Rooms and prices screen: add a room, edit a price, show the over-allocation error and the remaining amount.
- JUnit: the RM1,500 example (RM650 / RM500 / RM350), a rounding remainder, a single room, a total above the rent, an occupied room counted in the sum.

## Constraints

- Utilities are shared equally and are not priced per room.
- Flow B and C (groups and evaluations) need the total to equal the rent exactly; that rule is E9.1 and E9.2, not this story.
- Absent master, several masters and a tiny rent are not defined in the contract yet; agree before coding the edge cases.
