## Description

A request or message nobody sees is wasted. P1 adds push notifications for new requests and chat messages and an in-app list. The schema proposes a `notifications` collection (recipientUid, title, body, type, data, read, createdAt).

Notification types the app needs are few: a new Connection request, a request accepted or declined, a new chat message, a chore reminder (E7.5) and a rule change that needs acceptance (E7.6). Each push opens a screen, so the payload carries only an ID and a type, never message text or contact details (the lock screen is not private).

## Work needed

- Send FCM push for a new request and a new chat message.
- Tapping a notification opens the right screen.
- Notifications screen listing the latest items with a read state.
- Decide the sender: Firebase triggers are not on the free plan, so the Worker or the app must send.
- Store the device token per user in a private document; remove it on log out.
- Payload with `type` and an ID only; the app loads the content after the screen opens.
- Notification settings: let the student mute a type.
