## Description

The Messages screen is where requests are accepted or declined and where a Connection begins. A Connection is the moment two people may chat and see contact details; a Match alone never unlocks anything.

Two sources create a Connection: a Host accepting a listing request, and two students both accepting a match (`matches/{uidA_uidB}` with `statusA`/`statusB`). In both cases the Worker writes the `connections/{pairId}` document (ADR-0007), where `pairId` is the two UIDs sorted and joined by `_`, so Rules can find it without a query.

## Work needed

- Messages screen with a Requests tab: accept or decline, showing the sender's Match-stage fields and message.
- Accept creates the Connection and opens the chat (`chats` document with the two `participantUids`).
- Decline closes the request; the sender sees a neutral status.
- Rules (Gathan): what each stage may see; contact details only after both accept; `connections` readable only by the two people, either may set `ended`.
- Emulator tests for each stage.
