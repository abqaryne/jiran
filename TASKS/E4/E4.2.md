## Description

On the detail page the student sees a commute options card: each travel mode side by side with travel time, monthly cost and estimated CO₂, and the cheapest option that still arrives on time highlighted. This is the main reason to choose Jiran over a Telegram group.

Aaron's `getCommuteOptions` already returns the ordered options (walking, transit, e_hailing, driving), `selectedMode`, `trueMonthlyCostSen`, plus per-option `durationSeconds`, `distanceMetres`, `monthlyCostSen`, `co2GramsPerTrip`, `emissionSource`, `arrivesOnTime`, and, for unavailable options, a reason (`missing_route`, `missing_schedule`, `missing_fare_assumption`, `provider_unavailable`).

## Work needed

- Commute options card: one column in P0, each mode row with time, monthly cost and CO₂.
- Highlight the cheapest on-time option; when none arrives in time show the message and highlight nothing.
- Show sources and warnings as plain text; label every figure as an estimate; name the e-hailing fare assumption.
- Unavailable rows show the reason in words, never zero cost.
- Use the stub from `docs/engineering/api-contracts.md` until E3.3 is wired; show UM shuttle times only if seed data exists, labelled scheduled.
