## Description

A Connection request is how a student reaches a Host without sharing contact details. It becomes a Connection only when the Host accepts; until then the Host sees the same facts as a Match plus the short message.

Data: `listingRequests/{listingId}_{requesterUid}` (requestId, listingId, hostUid, requesterUid, message, status, createdAt, updatedAt). The deterministic ID lets Rules find the request with `get()`.

## Work needed

- Send request sheet with a short required message; creates the request with `status: 'pending'`.
- One open request per student per listing; the student can cancel (`status: 'cancelled'`).
- The Host sees initials, faculty, year, tags and score (when known), not the name, photo or phone.
- Rules: the requester creates only `pending`; only the Host (`listings/{id}.ownerUid`) sets `accepted` or `rejected`.
- Emulator test: a non-participant cannot read the request.
