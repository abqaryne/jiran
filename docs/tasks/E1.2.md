- **Branch / PR:** `feature/e1-signup`, PR #9 (merged 30 Oct 2026, with E1.1 and E1.4)

## Why

A student who closes the app must come back to the same place, and a student who forgets a password must not be locked
out of housing. The login screen is also the easiest place to leak who has an account, so it must not tell which
email is registered. See [PRD FR1.2](../product/PRD.md#module-1-authentication-and-verified-profile).

## Where it stands (30 Oct 2026)

Code and tests are merged on `main`. Checked on the Pixel_9 emulator with the local Auth emulator on 27 Oct: wrong login,
reset, log out, log in again, and killing the app with an unverified account. Not verified: a real device, a real
inbox, the live project, rotation, TalkBack, and Firebase's "too many attempts" message. In QA in ClickUp; hours not
logged.

## What to build

1. ✅ **Log in and Reset password screens** (`LogInFragment`, `ResetPasswordFragment`, their view models, `LogInCheck`).
2. ✅ **One message for a wrong email and a wrong password** (`INVALID_CREDENTIALS`), so the screen never says which was wrong.
3. ✅ **Reset password always says "if this email has an account, we sent a link"**, including for an unknown address,
   so the screen cannot be used to find out who is registered (`FirebaseAccountService.sendPasswordReset`).
4. ✅ **Session routing** at app start (`LauncherActivity` + `StartRoute`): signed out goes to Welcome, signed in but
   unverified goes to Verify email, verified goes to the product shell. The session is read without a network call.
5. ✅ **Logging in with an unverified account** goes to Verify email, not to the product.
6. ✅ **Log out** returns to Welcome. The button is on the Home placeholder for now (see Decisions).
7. ✅ **Tests**: `LogInCheckTest`, `LogInViewModelTest`, `ResetPasswordViewModelTest`, `StartRouteTest`.
8. ✅ **Tooling**: a shared Android Studio run configuration `android/.run/app.xml` that starts `LauncherActivity`, so
   nobody opens the component gallery by accident.

## Acceptance (how QA checks it)

- [ ] Log in with a wrong password and with an unregistered email: the same message appears for both.
- [ ] Reset password with a registered and an unregistered address: the same confirmation appears for both.
- [ ] Log in with a verified account opens the product; kill the app and reopen: it opens the product again.
- [ ] Log out returns to Welcome; the back button does not return to the product.
- [ ] Log in with an account that has not verified its email goes to Verify email.
- [ ] Press log in with empty fields: each field shows "required" under it and nothing is sent.
- [ ] `./gradlew testDebugUnitTest` passes.

## Deliberately not in scope, and why

- **A "remember me" switch.** Firebase keeps the session on its own; the PRD does not ask for a choice.
- **Changing the password inside the app.** Not in FR1.2; reset by email covers forgetting it.
- **Locking the account after failed attempts.** Left to Firebase's own limit; the app only shows its "too many attempts" case.
- **A "link works for 1 hour" text.** Figma showed one; the real expiry is not verified, so it was left out.

## Decisions taken

- 27 Oct 2026, Ary: wrong email and wrong password give one message; reset reports success for an unknown address. Reason: privacy of who has an account.
- 27 Oct 2026, Ary: the Log out button is temporary on the Home placeholder until Profile and settings (E10.1).
- 29 Oct 2026, Ary: a shared run configuration opens `LauncherActivity` (the debug build has three launcher icons: Jiran, Jiran dev, Jiran UI).
