# E1.4: Home and the four tabs after sign-in

- **ID:** E1.4
- **FR and priority:** none (the shell every flow lives in), P0
- **Owner:** Ary
- **Due:** 22 Nov
- **Depends on:** E1.2
- **Blocks:** E3.1 (Rooms), E6.1 (Match), E7.3 (Unit), E2 (Post button): each fills its tab or button
- **ClickUp:** story task `E1.4 Home and the four tabs after sign-in (P0)`
- **Branch / PR:** shell in PR #4 (E0.3); routing from sign-in in PR #9. Both merged.

## Why

After sign-in the student needs one place with the four tabs of the PRD navigation (Home, Rooms, Match, Unit) and a Post
button. The other owners can build their screens only when this shell exists and each tab has a place to plug into.

## Where it stands (30 Oct 2026)

The shell exists and opens after a verified sign-in. The four tabs show placeholder fragments and the Post button does
nothing yet. Home carries the temporary Log out button. No dedicated tests: routing is covered by `StartRouteTest`, the
rest by hand. Not verified on a real device. In QA in ClickUp.

## What to build

1. ✅ **Make the shell the first screen after sign-in.** `LauncherActivity` opens `ShellActivity` when the session is verified.
2. ✅ **Four tabs** Home, Rooms, Match, Unit in `nav_main.xml`, each a placeholder fragment, with the floating `JiranTabBar`
   highlighting the current tab.
3. ⚠️ **The Post button** is on the tab bar but its click handler is empty (it carries a note for Module 2). Gap by design: E2 builds the Post flow.
4. ⬜ **Profile gate.** Today a verified account goes straight to the shell. Once E1.3 exists, an account without a
   finished profile must go to profile setup first. Not built; it belongs to E1.3.

## Acceptance (how QA checks it)

- [ ] After verifying the email, the app opens on Home with the four tabs visible.
- [ ] Tapping each tab shows that tab and highlights it; tapping the current tab does not stack screens.
- [ ] Tapping the Post button does nothing and does not crash (until E2).
- [ ] Closing and reopening the app with a verified account lands on Home.
- [ ] The tab bar buttons are at least 48 dp.

## Files and tests

`ui/shell/ShellActivity.java`, `res/navigation/nav_main.xml`, `res/layout/activity_shell.xml`,
`ui/common/JiranTabBar.java`, `ui/home/HomeFragment.java`, `ui/auth/LauncherActivity.java`, `StartRoute.java`.

## Deliberately not in scope, and why

- **Real content in the tabs.** Rooms is E3.1, Match is E6, Unit is E7.3, and Home's real content is not in a story yet.
- **The Post flow.** E2 (Gathan) builds it behind the Post button.
- **Deep links and push notification targets.** Notifications are E5.4 (P1).

## Decisions taken

- 27 Oct 2026, Ary: single-activity shell with one navigation graph for the product and one for the Starting Flow.
- 30 Oct 2026, Ary: the product shell opens after verification as a stand-in until profile setup (E1.3) exists.
