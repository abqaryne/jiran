a seeded area and type the Building name. No Google Places, geocoding calls,

## Try it

Build `android/` debug, open **Jiran UI**, then **Preview Building picker
(sample data)**. Enter a fictional Building name, type `Sample` in the area
field, choose an option, and select **Use this Building**. The gallery displays
the result. Typing an area name alone must not enable confirmation. The preview
is debug-only and uses explicitly fictional coordinates; it makes no network
requests or database writes.

## Read and explain

| Piece | Responsibility |
|---|---|
| `AreaOption` | Validates the public area ID, display name and finite coordinates; never substitutes missing coordinates with zero. |
| `FirestoreAreaSource` | Reads `areas` from the server after the UM account check; Rules remain authoritative. Empty, unauthorized, malformed and unavailable data fail safely. |
| `BuildingPickerViewModel` | Requires a valid Building name plus explicit area selection; edits invalidate the prior selection; retries and restored state are revalidated. |
| `BuildingPickerDialog` | Existing tokens/styles, word-and-icon states, accessible controls, scrollable content and a Fragment result. |

The query reads at most 501 records and reports invalid data if more than 500
exist, rather than silently truncating the area catalog. These are defensive
implementation bounds, not measured product numbers. The area list filters
locally through Android's autocomplete adapter. Name normalization removes
extra whitespace and normalizes Unicode; it does not establish that different
spellings identify the same real Building.

## Subtask 3 integration contract (not implemented here)

Show `BuildingPickerDialog` and register a FragmentResultListener on the same
FragmentManager for `BuildingPickerDialog.RESULT_KEY`. Optional arguments
`buildingName`, `areaId`, `areaName` prefill a previous selection. State is also
saved across recreation and revalidated against the freshly loaded area list.

Result keys: `buildingName`, `areaId`, `areaName`, `areaLatitude`,
`areaLongitude`, `coordinateSource = area_center_estimate`, and `sampleData`.
Reject sample data in the real posting flow. The result is **not** a Listing
write payload; do not send it unchanged to the Worker.

No `placeId` or `exactAddress` is fabricated. Area coordinates must not be
presented as verified Building coordinates. The Worker from subtask 1 currently
requires `lat`, `lng` and a private exact address. Agree the estimate/source
mapping and private address capture before integrating the complete Post flow.
