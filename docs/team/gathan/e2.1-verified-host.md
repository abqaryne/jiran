Local implementation; Gathan approved the local commit on 9 Nov 2026. No live configuration change.

## What to read and explain

| Layer | What enforces the requirement |
|---|---|
| `VerifiedHostPolicy` | Requires the original form UID, verified email and the existing exact `siswa.um.edu.my` domain policy. Staff and look-alike domains fail. |
| `PostListingFragment` | Checks on entry/resume and token/session changes. Invalid or switched accounts lose access to the form; private in-memory form data is cleared and the activity stack restarts through the existing auth flow. |
| `WorkerListingGateway` | Binds requests to the original UID, refreshes the Firebase ID token before each write, checks verified/email claims and rechecks the account before sending and delivering results. |
| Worker + existing Firestore Rules | Firestore verifies the caller token and permits only a verified UM Host to create/write their draft. The Worker reads the private draft before calling the photo provider. UI checks are not authorization. |

**Needs human review:** authentication boundary, ownership and private data handling.
No Host role, custom claim, badge or extra registration fields are introduced.
The debug sample form bypasses the session guard only in its debug-only subclass;
it uses a fake gateway and cannot upload or write data.

## Verification and how to try it

Use only disposable accounts in `demo-jiran`; never real student data. Start
Auth and Firestore emulators, then run the required Android checks and:

```powershell
./gradlew.bat connectedDebugAndroidTest '-Pandroid.testInstrumentationRunnerArguments.class=com.jiran.app.VerifiedHostScreenTest'
```

The device cases open Post while signed out, as an unverified student, as a
verified staff account, and as a verified student who subsequently signs out.
Expected routes: Welcome, Verify email, Welcome, and Post then Welcome.
Verification in these tests is set by the local Auth emulator, not a real inbox.
Pure JUnit cases cover account switching and domain look-alikes. The save model
test checks that a late callback after ending the session cannot start uploads.

`backend/scripts/product-rules-smoke.cjs` now also invokes the actual Worker
handler with emulator-issued tokens and the real emulator Rules. It checks
ineligible draft creation, non-owner/ineligible photo uploads, the private
address boundary and the valid Host path. Cloudinary is intercepted by a local
test stub; rejected requests must make zero provider calls. No external upload.

See Gathan's AI log for actual results and failures. E1.1's task notes still refer
to Rules as missing; Ary should reconcile that historical gap with this evidence
and E0.5 without treating it as real-inbox or full E1.1 QA completion.

poll the Auth server. Fresh tokens and Firestore Rules guard writes. This does
not prove immediate server-side revocation of every previously issued token.

draft may remain, and the existing lifecycle/reconciliation limitations apply.
