## Configuration and failure handling

After Aaron verifies the existing Free Worker, provide its public origin through
the local Gradle property `listingApiBaseUrl`. Default is empty (saving unavailable).
No credentials belong in that property. HTTPS is required; debug emulator builds
also permit `http://127.0.0.1:<port>` with an explicitly configured adb reverse tunnel.
No live endpoint, provider account, billing or deployment was configured here.

Saving creates a Host-only draft then uploads each selected photo. Success means
the server acknowledged every photo. Fields lock after draft creation so a retry
cannot silently mismatch the saved draft. Explicit rejected requests can retry;
timeouts/5xx/malformed successes block retry because a write may already exist.
There is no automated reconciliation or My Listing recovery screen yet.
Interrupted process recreation reports unknown outcome if a write had started.
Unsaved private form data and image bytes live only in the ViewModel: rotation
retains them, process death or leaving discards them. Saved drafts are not deleted
when leaving. Draft editing/resume and cleanup remain lifecycle follow-up work.

Photo engineering limits: 5 selected images, 20 MiB source input, decoded longest
edge at most 1600 px, JPEG quality 85, uploaded image at most 2 MiB. These are
defensive bounds, not surveyed product values. Gallery images can still show
private information in their pixels; the UI asks the Host to choose accordingly.
Cloudinary image links are public even while draft documents are private.
