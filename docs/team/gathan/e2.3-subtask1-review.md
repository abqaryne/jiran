## Limits for Ary and the owner

- **Current Rules deny persisted renewal and closure** (`expiresAt` immutable, status unchanged). Client writes are implemented and surface failure; no bypass or successful live-write claim. Subtask 3 must implement and test authorization separately. The local effective state still becomes Expired/Closed on read.
- E2.2 publication is not implemented in merged code: drafts cannot be renewed or shown as published. No publication feature added here.
- Search is still a placeholder (E3.1/E3.2); its future query must use `status == active` plus `expiresAt > now`, and vacant Rooms. My listing deliberately reads expired/closed listings too.
- Acceptance changes only the request. Worker-created `connections`, chat and move-in remain E5 work. Client clock determines renewal time; server-bound validation/time enforcement belongs to Rules/backend follow-up.
- Closure is reconciled when the Host loads My listing, not by a scheduled process. Without a Host read, future E5.3 occupancy writes must close atomically to prevent stale public status.
- Request inbox uses refresh/on-return reads, not a live listener. It loads all requests for this Listing; pagination is not implemented. Host lookup chooses the most recently updated published Listing, with direct `listingId` supported by the Fragment.
