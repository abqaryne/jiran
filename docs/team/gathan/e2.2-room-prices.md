## Try the demo

1. Install the debug APK and open **Jiran UI → Preview Rooms and prices (sample RM1,500)**. It uses the production editor with an in-memory repository; no Firebase writes.
2. Tap **Apply suggested split**, confirm, and check master RM650, medium RM500, small RM350.
3. Toggle master to **Occupied** and change its price to **650.01**. Remaining shows **over-allocated by RM0.01** and Save is disabled. Occupied Rooms count too.
4. Set master to **650**. Add another Room via the type chooser: its blank price blocks Save until entered (zero is allowed). Remove the new Room to return to three.
5. Rotate: edits survive. Tap **Save Rooms**: the sample confirms an in-memory save. **Done** closes the preview.

Product entry: Post → save draft/photos → **Continue to Rooms and prices**. The repository reads all Rooms for the Listing and `config/app`. A config update changes the weights used by the next explicit split; it does not overwrite manual prices. Missing/unavailable config uses labelled draft estimates; invalid weights disable suggestions but leave manual editing available.

## Persistence design to explain

- Every Room carries `roomId`, `listingId`, `type`, integer `priceSen`, `status` and timestamps. `occupiedByUid` is preserved for an existing occupant and removed on switching to vacant. Marking a new Room occupied does not invent a user identity or create Household membership.
- A server transaction checks the loaded Listing and Room snapshots, validates every price, writes all Rooms and updates the parent `updatedAt` together. This serializes additions from this editor. Stale or unconfirmed saves require a reload; stable IDs prevent duplicate additions on retry.
- Drafts only. No publication/lifecycle endpoint was added. Previously saved Rooms cannot be removed here; new unsaved rows can be removed. The editor bounds transactions to 100 Rooms and refuses oversized loads instead of dropping Rooms from the sum.
- Rotation retains the ViewModel; process death reloads saved Rooms and discards unsaved edits. The screen does not persist private fields to instance state. Host account changes clear the editor and leave the screen.
- No utilities fields or prices are added. The existing Room card already separates rent from one-way commute estimates.
